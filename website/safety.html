The honesty page

Everything that can go wrong, in our own words.

An adversarial review of this project opens by calling it “a consumer-grade disk-destruction tool with a wizard on it”, unless every hard stop it lists is built. It is right, which is why that sentence is on this page and not buried. Below: what is proven and where, what can still go wrong, what we will not do, and what this site used to say that was wrong.

The ledger

Kept item by item in docs/issues/v3/STATUS.md. The numbers are checks, and every test named fails when the thing it checks is broken.

Proven on real Windows (a Windows machine in GitHub Actions, on every push)

  • The installer starts the way a double-click starts it, and its pages navigate.
  • Check this PC reads the real machine without writing to it.
  • Fast Startup is switched off by the installer.
  • “Fix these for me” frees space: temp folders emptied, a link inside them removed as a link with the file behind it untouched.
  • The task that reopens the installer after a restart is made and removed.
  • The whole AurOS image downloads through the installer’s own code and checks out.
  • The published file, fetched from its public link and pinned by its checksum, starts.

Proven on simulated PCs (virtual machines with real UEFI firmware, Microsoft’s keys, Secure Boot on)

  • 37 checks

    An install, end to end, with a memory stick.

  • 45 checks

    An install and putting Windows back, without a memory stick, which is what the test build does.

  • 138 checks

    The power cut at 18 named instants; Windows back every time, every file byte-identical. Try it.

  • 32 checks

    The real image’s first start, and the firmware’s start-up list after it.

  • 9 checks

    The choices made in the installer arriving in AurOS.

  • 16 checks

    “Put Windows back” from the button in AurOS, through AurOS’s own menu, to the restore.

Not proven

  • A real PC’s disk being made smaller and written. The first real-PC attempt could not start the installer at all; that is fixed, and the next result is the next piece of evidence.
  • Bringing files across from a real person’s Windows. Tested only against test data (43 checks).
  • An install with antivirus running.

Not done

  • Code signing. Windows says “Windows protected your PC”, and on a PC with Smart App Control on it will not run the installer at all.
  • A memory-stick page in the installer. The engine and its tests exist; the page does not, so the test build installs without a stick.
  • Screen readers in the installer.
  • AurOS’s own words in other languages. Dates, numbers and programs with their own translations follow your language; AurOS’s menus are English for now.
  • Wi-Fi passwords, and Chrome or Edge passwords, carried across from Windows.
  • Email from Outlook files. Counted and reported, not converted.
  • Firefox. The published image ships the GNOME Web browser instead, because the build machine could not reach Mozilla’s servers.
  • Some updates. Ubuntu’s security updates install daily, except the kernel and the start-up programs, which are held back until updating them cannot drop AurOS’s start-up menu. AurOS’s own programs have no update path yet.
  • The other four images (office, school kiosk, revive, multilingual) are not rebuilt; only the desktop one is published.
  • Hosting. The image is downloaded from a branch of the source repository, which is fine for tests and not for a release.

What can go wrong

Worst first. Each has a real mechanism, and several have happened to people using other tools that do roughly this.

The power goes during the shrink the one bad row

Every other step is arranged so that a power cut leaves either the old layout or the new one. The shrink cannot be: the tool that resizes Windows’ filesystem only promises to survive an interruption when growing it. Cut there, the drive is treated as damaged; Windows’ disk check is the way back, and in the worst case files are lost.

What we do: refuse on battery, read the whole region that will be moved before moving it, put nothing else in that window, and say “Do not turn the computer off” there and only there. See it.

The drive was already failing our audience, exactly

Making room reads parts of the drive untouched for years, then writes gigabytes. On a drive that was quietly dying, that finishes it. And “your old PC” selects exactly the drives nearest the end.

What we do: read the drive’s own health first and refuse a failing one, with no override. A person told “your drive is failing, back it up today” is a person we helped.

The way back is on the drive it rescues test build

The design keeps the way back on a memory stick as well. The test build has no stick page yet, so it keeps the only copy on the same drive. If that drive fails, the way back fails with it. And from the start of the shrink until that copy is written, the only copy is in memory.

AurOS cannot drive part of the hardware most likely

Most often Wi-Fi, on laptops from the early 2010s; then graphics, screen brightness, sleep and sound. With no network there is no way to get help or fixes.

What we do: before the partition list changes, AurOS loads its own drivers on the real machine and looks for wireless or a network cable; with neither, it stops there. It reports brightness and sound but does not stop for them. There is no tested hardware list yet.

Antivirus stops it part way unsigned, new

Antivirus that judges files by how many people have run them will hold an unsigned new installer that asks for administrator rights and writes to the start-up list: it is exactly what they are built to be wary of. Before the restart the installer only reads the drive, downloads into C:\AurOS, writes under \EFI\AurOS and sets a one-time start-up entry, so being stopped there leaves Windows as it was. The test instructions say how to add an exception.

The drive is encrypted, and you did not know common now

Recent Windows switches on device encryption by itself on many PCs. An encrypted Windows partition cannot be made smaller, and resizing it wrongly destroys it.

What we do: the installer switches encryption off and waits for Windows to finish decrypting before going on. While it is off, the drive is not encrypted; switch it back on in Windows if you want it. Third-party whole-disk encryption is refused outright.

Windows was hibernating when it seemed shut down silent

With Fast Startup on, “Shut down” saves the running system instead. A Windows that wakes from that after its drive has changed writes back a stale picture of the drive.

What we do: switch Fast Startup off first, always, and check the drive’s own state again after the restart before touching it.

The PC starts the old way (BIOS), or has an unusual set of drives refused

On an old-style PC there is no way to ask the firmware to try something once and fall back by itself. Some multi-drive setups keep their real layout where our tools cannot read it. Both are refused, in one line, with nothing changed.

The tested firmware is not your firmware unknown

Every install so far ran on one virtual firmware. Real firmware from different makers and years has its own habits, such as a full list of start-up entries that ignores a one-time request. That is what installs on real PCs are for, and they have not happened yet.

What we refuse to do

Things that would get more installs, and that we are not doing.

No override

A stop is a stop. There is no “advanced” button and no “I understand the risks”. The installer will not even show the later pages while a stop is on the list.

No resizer of our own

Resizing Windows’ filesystem is done by a tool that has had twenty years of people trying to break it. Writing our own would be more fun and would eventually cost someone their drive.

No uploading your files

Windows stays on the drive and AurOS reads it, read-only. Nothing about your files leaves the machine.

No firmware menus, with one exception

If a PC is set to start only Windows, the installer shows the one setting to change and how to reach it. It does not ask for Secure Boot to be switched off.

No tricks around the warning

The fix for “Windows protected your PC” is a signature, which needs a legal entity and a certificate. For the test build we do tell testers to press “Run anyway”, because there is no other way to test it. A public release waits for the signature.

No telemetry, no tracking

Every AurOS profile ships with telemetry off. This website has no analytics and no cookies, and loads nothing from anywhere else.

What cannot come across

AurOS writes a report of what did not come, instead of leaving you to find the gap a week later.

  • never

    Windows programs

    They do not run on Linux. If you depend on one (a tax program, a printer’s own tool), keep Windows.

  • never

    OneDrive files that are only online

    They are on Microsoft’s servers, not on the drive. Make OneDrive keep them on this device first; the installer’s backup page says how.

  • not yet

    Wi-Fi passwords

    The networks come across; each password is typed once.

  • not yet

    Passwords and cookies saved in Chrome or Edge

    Reported, not carried.

  • not yet

    Email in Outlook files

    Counted and reported, not converted.

  • yes

    Documents, pictures, music, videos, downloads, the desktop; time zone, language, keyboard

    Read from the Windows partition, which is mounted read-only and checked to really be read-only. Tested against test data, not yet a real person’s.

Errata

Things earlier versions of this website said that are no longer true, or never were. Kept here so nobody is left believing them.

What this site used to say.

  1. “One evening, two restarts.”

    One restart. The install and the hand-over to AurOS happen in the same boot.

  2. “On first boot you will see one firmware screen asking you to approve our key.”

    No. AurOS starts through Ubuntu’s Microsoft-signed shim, and nothing is enrolled. The only firmware screen is the rare Secured-core setting above.

  3. “No install without a rescue USB.”

    That is still the design. The test build installs without a stick, because the installer has no page to choose one yet, and keeps the way back on the disk.

  4. “Type back part of your 48-digit recovery key.”

    The installer switches BitLocker off and waits for Windows to decrypt instead.

  5. “Your Wi-Fi passwords come with you.”

    The networks do; the passwords do not, yet.

  6. “The only thing on offer is a read-only check.”

    There is a test installer, for spare PCs. Download.

  7. “Nocturne: blue-black with an aurora-teal glow.”

    Nocturne was redrawn in brass on near-black. The theme file still carries the old one-line description, and the screenshots on this site still show teal.

Before a public download

What stands between this and a real release is not code.

A legal entity, a code-signing certificate, a proper host for the image, insurance, and a list of real PCs it has been tested on. Nothing ships to the public until the dry run has been through a set of real machines and an install has been made to fail at every phase on real hardware.
