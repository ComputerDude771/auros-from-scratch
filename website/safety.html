Safety

Everything that can go wrong, in our own words.

A hostile review of this product summed it up as “a consumer-grade disk-destruction tool with a wizard on it”. That verdict is on this page rather than buried in a repository, because the work that followed it is the reason the product is worth shipping at all. Here is what we found, what we built in response, and what remains genuinely dangerous.

The five things that must be true

These are the conditions for shipping. If one of them stops being true, the correct response is to stop shipping, not to add a warning dialog.

  1. The installer can always put the machine back. The rescue area is written before the first destructive byte, and is reachable from the boot menu without a USB stick, a second computer, or us.

  2. Nothing irreversible happens until the new system has booted and you have said it works. Windows stays bootable and stays the default until you choose otherwise.

  3. We know the machine before we touch it, and we refuse the ones we cannot handle. Refusing is a designed product outcome, not an error dialog.

  4. Hardware support on old PCs is the unpriced risk. We test your Wi-Fi, screen and sound from the rescue environment before committing anything.

  5. A real legal entity, insurance and a lawyer-drafted consent flow exist before the first public download. They do not yet. That is why there is no public download yet.

What can go wrong

Ordered by how much damage each one would do. Every item is a real failure mode with a real mechanism — several of them have already happened to people using other tools that do approximately this.

Windows encrypted your drive and you never knew highest consequence

What happens: recent Windows versions switch on device encryption automatically when you sign in with a Microsoft account, and recent releases relaxed the hardware requirements, so far more machines are encrypted than their owners believe. Changing the disk layout changes what the security chip measures at startup. The next time Windows starts, it asks for a 48-digit recovery key you have never seen — stored in a Microsoft account you can only reach from a browser, on the computer that is now asking for the key.

Why it is the worst one: we would have destroyed your data while trying to preserve it, after promising Windows would stay intact. That is worse than wiping the disk, because you trusted us.

What we do: detect the encryption state before anything else. Require you to type back part of the recovery key, not tick a box — proof you can actually get in afterwards. Offer to save and print it, and write it into the rescue area. Suspend protection in a way that does not silently expire after one restart. If the key cannot be produced at all, we stop, and there is no override.

One disclosure that matters: while protection is suspended, your drive is not encrypted at rest. Turn it back on when the install is finished.

Windows was hibernating when you thought it had shut down silent, hours later

What happens: “Shut down” on Windows 8, 10 and 11 usually saves the running system to a file instead of really shutting down. If Windows later resumes from that saved image after we have changed the disk, it writes back its old, now-wrong map of the disk. Both operating systems are destroyed — silently, and typically hours after everything appeared to work.

What we do: we detect it two ways, require the feature to be switched off, force a genuine restart, and then verify the flag is actually clear before continuing. We never offer a Windows boot entry that could resume a stale saved session. Notably we do not use the common workaround that forces the volume clean, because it quietly throws away whatever you had unsaved.

The install fails halfway and this is your only computer product-existence risk

What happens: the install stops at 70%. The boot path is half-changed, AurOS does not start, Windows does not start, and your photographs are on a partition you cannot reach. You have one computer, no USB stick and no second machine. This is not a support problem, it is the problem that decides whether the product should exist.

What we do: the rescue area is written first, and is bootable from the machine’s own menu. We never remove the ability to start Windows until you have confirmed the new system works. The first AurOS boot is a one-shot request to the firmware that reverts itself if it fails. And the rescue USB is mandatory, because the rescue area cannot help if the disk’s layout itself is what broke.

Where there is no mitigation: a person with one computer, no USB stick, no phone and no second device. For them there is nothing we can build. We gate them out at the front door instead, and that is the right answer.

Your hard drive was already failing our market, exactly

What happens: making room moves files around, reading sectors that have not been touched in years, and then writes several gigabytes. That is the most demanding thing that drive has ever been asked to do. A disk that was quietly dying finishes dying during our install.

Why it concentrates here: our entire pitch is “your old PC”. We are selecting for exactly the population of drives that are near the end.

What we do: read the drive’s own error counters first and refuse on any pending or uncorrectable sectors, with no override. Read-verify the region we intend to reclaim before committing to anything. Read back and verify every block we write.

A person told “your hard drive is failing, back up today” is a person we saved. A person whose drive dies during our install is one we killed. The refusal is the feature.

The power goes out at the wrong second irreducible

What happens: the table describing your disk’s layout has no undo log. Neither does the movement of data during a resize. Lose power in the middle and the disk can be left describing itself incorrectly.

What we do: arrange the work so there is exactly one moment that matters. All the data movement happens first, with the old layout still in force and still correct; then everything is verified; then the new layout is written as a single small write. We keep a pristine copy of the original layout in two places, keep a journal on disk so a restarted installer knows which step it died in, and refuse to start on battery or below 50% charge.

This is the one item on this page that careful engineering genuinely shrinks rather than removes. The window is small. It is not zero.

Windows will not give up as much space as you have free the normal case

What happens: Windows can only shrink a volume from the end, and refuses to move several of its own large files while it is running. A disk with 30 GB free commonly offers 2 GB. This is the usual outcome, not the unlucky one.

What we do: we do not shrink from inside running Windows. We do it from the rescue environment with Windows not running, using the standard long-established tool, after a clean disk check. Hibernation, the page file and old restore points are dealt with first — all disclosed, and everything except the restore points is reversible.

Your PC boots the old way, not the new way refused

What happens: on older machines that start in legacy BIOS mode, there is no way to ask the firmware to try an operating system once and fall back by itself. Get the boot record wrong and the machine shows a blinking cursor and nothing else. There is a second trap: that style of disk allows only four main partitions, and a typical manufacturer’s Windows 10 layout already uses all four. A fifth one cannot be created at all.

What we do: refuse. A far better funded project shipping real hardware failed for 20–30% of users on these machines doing approximately what we do, and concluded that dual-boot was for evaluation rather than daily use. We would rather send you to a mainstream distribution installed from a USB stick than be the 25%.

The filesystem was already damaged refused until clean

What happens: feeding a filesystem with a damaged index into a resizer turns “a few unreadable files” into “a disk that will not mount”.

What we do: require a clean full disk check before we proceed, refuse while the volume is flagged dirty, and refuse if the check reported that it had to correct anything. On an old spinning drive that check can take hours; we design the waiting screen for it rather than skipping the check.

Your disk is not the shape it appears to be refused

What happens: Windows dynamic disks and Storage Spaces keep the real layout in a private database; the ordinary partition table is decorative, and a tool that believes it gets the geometry completely wrong. Separately, some PCs present their drive through an Intel remapping layer that Linux may not be able to see at all — the fix for which is a firmware setting we will not talk a non-technical person through.

What we do: detect all three and refuse cleanly on dynamic disks and Storage Spaces. On Intel remapping we warn, and then verify from the rescue environment that AurOS can actually see your drive before anything is committed. If it cannot, nothing is changed.

We write to the wrong disk cheap to prevent

What happens: an old desktop with a small system drive and a large second drive holding fifteen years of photographs. Or an external backup drive plugged in during the install. Pick the wrong one and the damage is total.

What we do: list every drive with its model, size and a sample of what is on it; require you to type the target drive’s size or label back; and refuse to run at all while removable drives are attached. This prevents an entire category of catastrophe for almost no engineering cost, so there is no excuse for not doing it.

The small area that starts your operating systems is already full common on OEM PCs

What happens: manufacturers often ship that area at 100 MB and already 85–95% full. Reformatting it to make space destroys Windows’ ability to start.

What we do: measure the free space first; create our own area rather than clearing yours if there is not enough; never reformat the existing one; keep our own boot files small; and back the whole thing up into the rescue area before touching anything.

Linux does not support some part of your hardware highest frequency

What happens: this is the most likely thing to go wrong, by a wide margin, and the most likely single victim is Wi-Fi. A large family of wireless chips found in 2010–2016 laptops is split across several drivers with conflicting requirements per revision. No Wi-Fi means no internet, no documentation, and no way for us to send you a fix — and it is invisible until after the restart. Old NVIDIA graphics, screen brightness controls, sleep and audio all have their own versions of this.

What we do: test Wi-Fi, brightness, sound and sleep from the rescue environment, on your actual machine, before committing anything. If Wi-Fi will not come up there, we abort and leave Windows alone. This single decision is worth more than every other mitigation on this page.

Honest context: Google ships its own old-PC operating system with a list of certified models and three support tiers, and does not guarantee anything outside that list. If Google needs a whitelist, so do we, and we do not yet have one. On unlisted hardware the honest answer is that we find out together, in an environment designed so that finding out costs you nothing.

What we refuse to do

A list of things that would make this product convert better, and that we are not going to build.

No override checkboxes

A hard stop is a hard stop. There is no “advanced” toggle, no “I understand the risks, continue anyway”, no hidden command line flag that bypasses the disk health refusal. If we let people click past it, the people who click past it are exactly the ones who lose their data.

No install without a rescue USB

We know what mandatory hardware requirements do to conversion rates. We are taking the hit. The rescue area on the internal disk cannot save you from a damaged disk layout, and that case is the one that ends with an unusable computer.

We will not upload your files

An earlier design moved your files to cloud storage and pulled them back afterwards. We rejected it. Keeping your Windows partition and reading it from Linux is safer, faster, free, private and reversible. Your data does not leave the machine.

We will not write our own resizer

Resizing a Windows filesystem is a solved problem with a mature implementation that has been attacked for twenty years. Writing our own would be more fun and would eventually cost somebody their disk.

We will not talk you through firmware menus

“Press F2 at boot, find the storage setting, change it from RST to AHCI” is how a working computer becomes a non-booting computer over the phone. If a machine needs a firmware change, we refuse the machine.

We will not teach you to click past security warnings

Until our installer is properly signed, Windows will warn about it, and on some PCs will refuse to run it. Writing a friendly guide to bypassing that would train a habit worth more to you than we are. The fix is ours to make, not yours.

No telemetry, no accounts, no tracking

AurOS ships with telemetry off and there is no setting that turns on anything more than anonymous. The installer works with the network cable unplugged. This website has no analytics and sets no cookies.

No shipping before the rescue path is tested

Nothing that shrinks a partition ships until the rescue area and the “Put Windows back” button exist and have been tested by deliberately failing an install at every single step. That work is why there is no public installer download on this site today.

What we cannot bring across

At the end of the move you get a screen listing everything we could not bring. Here is that list in advance, so it is not a surprise afterwards.

Your Windows programs

Windows applications are Windows applications. They do not run on Linux and we do not pretend they do. You get open alternatives for browsing, documents, photographs, music and video calls, and for most people that is the whole list. If you depend on one specific Windows-only program for work, keep Windows in the boot menu — which is exactly why we leave it there.

Saved passwords, without your old Windows password

Windows encrypts your saved passwords with a key derived from your Windows sign-in password. Without that password they are not difficult to recover offline — they are mathematically impossible.

  • Chrome, Edge, Brave passwords and cookies: only if you type your old Windows password when we ask. Skip it and we say plainly that they were skipped.
  • Firefox passwords: these do come across, because Firefox does not use the Windows mechanism. Unless you set a Primary Password, in which case you will need it.
  • Windows Credential Manager, remote desktop credentials, saved app tokens: not recoverable. Same reason.

A Windows Hello PIN is not the same thing as your password and does not unlock any of this.

OneDrive files that are only in the cloud

Files shown in your OneDrive folder that have not been downloaded are not files. They are markers pointing at a copy on Microsoft’s servers. Copying one gives you a stub or an error, not your document.

This is the single most dangerous invisible way to lose data in a migration, so we count them, show you the number, and never silently skip them or silently copy the stubs. The fix is to make OneDrive download them before you start, or to sign in to OneDrive afterwards from Linux.

Everything else on the list

  • Files you encrypted with Windows’ own file encryption
  • Anything on a locked encrypted volume we were not given the key for
  • Purchased books, films and music with copy protection
  • Software licences, activations and product keys
  • Outlook’s offline mailbox and the Windows Mail store — re-add the account instead and let it sync
  • Printer and hardware drivers
  • Fingerprint and face sign-in, and anything sealed to the security chip
  • Passkeys stored in Windows
What does come across, for balance

Your documents, pictures, music, video, downloads and desktop — found properly, by asking Windows where you actually keep them rather than assuming. Your saved Wi-Fi networks and their passwords, which work offline without your Windows password, so you are online immediately. Your whole Firefox profile: bookmarks, history, open tabs, cookies and logins. Your language, keyboard layout, time zone, wallpaper and accessibility settings. Bookmarks and history from Chrome, Edge and Brave.

The firmware screen you will see, and why

Most PCs only start software signed by a key their firmware already trusts. Getting a new operating system added to that list requires a legal entity, a review process measured in months, and a certificate we are in the process of arranging. We are not going to tell you to switch Secure Boot off — that is a real reduction in your computer’s security and it interacts badly with Windows’ own encryption.

What happens instead: on your first start, the firmware shows one blue screen asking you to approve our key. It is one screen, it happens once, and the installer shows you what it will look like before it appears so it is not a surprise. If you are reading this on a very old PC, there is an additional honest caveat: the industry changed signing keys in 2026, and some older firmware cannot be updated to recognise the new ones. On those machines we may never be able to offer a no-prompt start.

And the Windows-side version of the same problem

Until our installer is signed by a recognised certificate authority, Windows will show an “unknown publisher” warning, and on a recently installed Windows 11 with Smart App Control on, it will simply refuse to run. For a product aimed at non-technical people, that is not a rough edge, it is a wall — and it is ours to remove, not yours to click past.

Where this project actually is

The most common way an ambitious systems project fails is that the interesting parts get built and the load-bearing parts do not. Here is our own status, without rounding up.

Built and working

  • The theme engine: inheritance, colour algebra, nine render targets, four themes
  • The wallpaper renderer, including its own image encoder — no image files anywhere in the system
  • The source-to-package build system, with dependency resolution
  • The installer’s read-only preflight, building as a native Windows program
  • The profile system this site’s organizations page describes

Not built yet

  • Every destructive installer phase: consent, rescue kit, shrink, write, boot handoff
  • The rescue environment and the “Put Windows back” path
  • The migration engine — specified in detail, not yet written
  • Code signing, the Secure Boot chain, and the update channel
  • A legal entity, insurance, and a lawyer-drafted consent flow
  • A tested hardware list
The thing most likely to kill this project

Our own assessment, written down so we cannot quietly forget it: the gap between the code that exists and the code that matters. Building a from-scratch operating system is a gravity well of interesting, tractable, aesthetically satisfying problems. Writing an image encoder is fun. Writing the encryption-detection path that correctly refuses to run is not. We have therefore put the installer’s safety engine ahead of further desktop work, and this page exists partly to keep us to it.
