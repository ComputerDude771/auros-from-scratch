Schools & organizations

One plain-text file describes the whole fleet.

A room of ageing Windows machines that are too slow for the current operating system and too functional to throw away is a common problem with an expensive default answer. AurOS is an attempt at a cheaper one: branding, language, the app list, and exactly what students are allowed to change, all in a single readable file that produces a bootable image.

Profiles

A profile is the entire customization surface of the system in one file. No scripts to maintain, no golden image to re-capture, no configuration management agent. Edit the file, build, deploy.

Inheritance, so you only write the differences

A profile can inherit from another and override only what differs. The default desktop profile carries the sensible defaults; a lab profile might change four lines. Your organization’s own base profile can in turn be the parent of per-room or per-year-group profiles.

It is data, not code

Everything on this page is a key and a value in a text file. That is a deliberate design constraint: the moment the lockdown story requires writing code, it stops being auditable by the person responsible for the machines, and that person is usually not a programmer.

The whole file is plain key="value" pairs with comments. It is readable by a person who has never seen it before, which is the point. 

# A locked-down lab build, in full.
inherit="desktop"

profile_id="lab-kiosk"
profile_name="Library Kiosk"

# Branding
brand_name="Your Organization"
theme="sandstone"

# One app, and nothing else
packages_apps="firefox"
packages_extra="cups-client"

# Policy
kiosk_mode="yes"
allowed_apps="firefox"
allow_user_install="no"
allow_settings_change="no"
allow_theme_change="no"
allow_tty="no"
auto_login="yes"
default_user="student"

# Fleet
enrollment_url="https://mdm.example/enroll"
update_channel="managed"
telemetry="off"

Eighteen lines, inheriting everything else from the default profile.

Lockdown

The policy section of a profile. These are the controls that exist today, named exactly as they appear in the file.

Every policy key in a profile, with its default.
Key Default What it does
kiosk_mode no Single application, full screen. No desktop, no launcher, no shell access. The machine starts, the app appears, and that is the whole system.
allowed_apps empty An allow-list. Empty means everything installed may be run; naming applications restricts to those.
blocked_apps empty A deny-list, for when an allow-list is too blunt.
allow_user_install yes Whether a signed-in user may install software at all.
allow_settings_change yes Whether the settings surfaces are writable or read-only.
allow_theme_change yes Whether users can reskin the machine away from your branding.
allow_tty yes Whether the text consoles behind the desktop are reachable. Set to no for exam and public-access machines.
auto_login no Start straight into the session with no password. Correct for kiosks; wrong for staff laptops.
default_user auros The account created at build time.
telemetry off Off, or anonymous. There is no third setting, and off is the default in every profile including the ones we ship.
update_channel stable stable for ordinary machines; managed to hold a fleet at a version you have tested.
enrollment_url empty An endpoint the machine checks in with on first boot, for organizations that already run a device management system.
What lockdown here means, precisely

These controls shape what the desktop offers and what the system will start. They are a good answer to “students should not be able to change the wallpaper, install games or reach a terminal”. They are not a claim to be tamper-proof against a determined, technically capable person with unsupervised physical access to the machine and the ability to boot it from a USB stick. Nothing at this layer is, in any operating system, and you should be suspicious of anyone who says otherwise. Full-disk encryption and firmware passwords are the layer that addresses that, and they sit underneath us, not in this file.

Languages

“Make these machines run natively in Chinese, or French, or Arabic” should be a profile edit, not a rebuild. It is.

A profile sets the system language, any number of additional languages, the keyboard layout and variant, and the time zone. The build then pulls in the input methods and the font coverage those languages actually need — which is the part that usually gets forgotten and produces a machine full of empty boxes where the text should be.

  • locale — the system language, e.g. fr_FR.UTF-8
  • extra_locales — additional languages available at sign-in
  • keyboard_layout / keyboard_variant
  • timezone
  • packages_extra — input methods and fonts

For a machine migrating from Windows, the language, keyboard layout and time zone are also read off the Windows partition during the move and shown to the user for confirmation — so a French-configured Windows becomes a French-configured AurOS without anyone choosing anything. 

# Four languages, ready at the sign-in screen.
inherit="desktop"

locale="fr_FR.UTF-8"
extra_locales="zh_CN.UTF-8 es_ES.UTF-8
                ar_EG.UTF-8 en_US.UTF-8"
keyboard_layout="fr"
timezone="Europe/Paris"

# Input methods and the font coverage those
# locales actually need.
packages_extra="ibus ibus-pinyin ibus-m17n
                 fonts-noto-cjk fonts-noto-core
                 fonts-noto-color-emoji
                 language-pack-fr
                 language-pack-zh-hans
                 language-pack-es language-pack-ar"

Right-to-left layout for Arabic and Hebrew is a desktop-shell feature that is implemented but has not been tested at the depth a deployment deserves. Ask us about it before committing to it.

Applications, and the one that decides procurement

For most school deployments a single question decides everything: does our state testing platform run on it? Those platforms usually mean Chrome specifically, not “a browser”. An earlier version of AurOS used a minimal system library that made prebuilt Chrome, Zoom, Teams and similar impossible to run at all. We changed it, from scratch, for exactly this reason.

The result is that mainstream Linux builds of browsers and conferencing clients install and run normally, and the browser comes from a real package repository rather than a container format that is slow to start on old hardware — which matters when the machine you are reviving is from 2014.

Test it, do not take our word for it

We will not claim your specific testing platform, proctoring client or classroom management tool works. Several of them are Windows-only, and some require a browser extension available only on a managed Chrome install. That is a pilot question, and the answer is either yes on your ten test machines or the project stops there.

What is not ready for you

If you are responsible for a few hundred machines, this is the section that matters. We would rather lose the deal than be discovered halfway through a rollout.

The installer is not finished

The read-only compatibility check is real and will honestly tell you how many machines in a room would be accepted. Everything that changes a disk is still being built. Nothing gets deployed to a student machine until the rescue path is tested by deliberately failing installs. Full status.

Every machine will show one firmware prompt

Until our boot chain is signed by a recognised authority, each machine needs a one-time approval on a firmware screen during its first start. On one laptop that is a mild curiosity. On two hundred it is two hundred people standing in front of two hundred screens, and you should price that in. Why.

There is no management console

There is a profile file, a build, and an optional check-in endpoint your existing device management system can answer. There is no dashboard, no remote command, no inventory service, no reporting. If your procurement requires one, we are not a candidate this year.

There is no certified hardware list

Comparable products ship with a list of tested models and tiers of support. We do not have one yet. What we have instead is a rescue environment that tests Wi-Fi, brightness, sound and sleep on each machine before anything is committed, and aborts if they fail — which turns an unknown model into a wasted twenty minutes rather than a broken computer.

There is no support contract

No legal entity, no insurance, no service-level agreement, no invoice to pay. All of those are prerequisites we have written down and not yet met. Any pilot today is a pilot with volunteers, on spare machines, with backups.

Dual-boot at scale needs a decision

Keeping Windows on every machine is the safety property that makes this product defensible, and it costs roughly half the disk. For a lab of small drives you may want the replace-everything path instead — which is supported, and which removes every undo described on this site. Decide that deliberately, not by accident.

What an honest pilot looks like

  1. Run the read-only check on every machine in one room

    It writes nothing and takes under a minute per machine. You get a list of which machines would be accepted, which would be refused, and why. Several of the refusals — failing drives especially — are worth knowing about regardless of whether you ever install anything.

  2. Write one profile for the room

    Branding, language, the app list, and the policy keys above. Inherit from the default and change only what differs. Expect this to take an afternoon, most of it spent deciding rather than typing.

  3. Install on spare machines that nobody depends on

    With backups, on machines that are not in a timetable. Then try to break the lockdown yourself, and try the restore path deliberately — boot the rescue entry and press “Put Windows back” on at least one machine, so you have seen it work with your own eyes.

  4. Put it in front of the people who will use it

    A teacher, a librarian, a student. The question is not whether it boots; it is whether the first hour of using it is confusing. If it is, that is our bug, and we would like to hear about it before you roll anything out.

Start with the check

It is the only part that is finished, and it is the part that tells you whether the rest is worth your time. It is read-only, it takes under a minute, and it changes nothing on the machine.
