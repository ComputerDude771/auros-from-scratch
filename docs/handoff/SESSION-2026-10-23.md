## Decisions

### D1. The slow work moves into Windows, while the download runs ("fast path")

Old: Windows only downloads and arms a restart; after the restart the
staging environment hashes the 5.3 GB image again, reads every free
sector of C:, shrinks NTFS to its minimum with ntfsresize, copies the
image, verifies, commits.

New: while she reads the wizard and the image downloads, **Windows
shrinks C: itself** (its own online shrink, the code behind Disk
Management; works with BitLocker on) by only what AurOS needs, and the
installer **writes the AurOS partitions raw into the freed, unallocated
space** as the pieces arrive (Windows refuses raw writes inside any
volume, which is a second fence), verifying as it goes. After the
restart, staging only checks the journal and the written regions,
saves the way back, commits the GPT in one sector, and starts AurOS:
about a minute.

Why: it is the only design that fits 10 minutes (the download is the
floor, and everything else hides behind it), and it is the only one
that installs on BitLocker/Device-Encryption PCs without hours of
decryption (Windows 11 24H2+ encrypts clean installs by default). It
overturns phases.h's old rule "nothing here writes to the computer's own
disk" on purpose: the shrink is reversible (extend C: back) and the
written region is referenced by nothing until staging commits the GPT.
The old staging-shrink path stays as the fallback for a PC where
Windows cannot shrink far enough.

BitLocker: protectors are suspended for a small reboot count before the
restart (the standard pre-firmware-change step) so Windows never asks
for a recovery key; nothing is decrypted.

### D2. Her Wi-Fi comes with her

The installer (already elevated) reads the connected Wi-Fi profile's
key and hands it to staging, which writes a 0600 NetworkManager keyfile
into AurOS and deletes the copy on the EFI partition. First boot is
online with nothing typed. Staging no longer requires a network at all.

### D3. The wizard is three screens and no typing

Check (automatic) → what will happen + pick the style, with pictures →
installing (download already running) → restart. No "type AGREE", no
backup checkbox gate, no drive model names; honest time for her PC.

### D4. Refusals that are not real dangers stop being refusals

Empty built-in card readers, eMMC system disks, a plugged-in USB stick
(warning only: the journal pins the target disk), "plugged in but the
battery is low/dead" (AC is what matters). Intel RST/VMD remapping that
Linux cannot see is refused in Windows, before anything, not after.

### D5. Software: Flathub in "Get more programs", reachable from every home screen

gnome-software + flatpak plugin + a vendored Flathub remote; polkit lets
the person install without a password; new programs appear without a
restart; Firefox from Mozilla's apt repo (the image is now built on
GitHub Actions, which can reach it).

### D6. Build, test and publish on GitHub Actions

The container this runs in has no KVM and its network blocks Microsoft,
Mozilla, Flathub and Google. Actions runners have KVM and open network,
and the repo is public (free minutes). So: images are built there,
published as GitHub Release assets (stable link
`releases/latest/download/...`), the website is deployed to Pages, and a
real Windows 11 evaluation VM (OVMF + Microsoft keys + swtpm) is driven
from the website to an installed program, with screenshots of every
step. az_serv (mentioned by the owner) is not reachable from this
session; Actions VMs replace it.

### D7. No code signing, ever (owner's decision, 2026-10-23)

"The whole point is to build another OS outside of Windows; I shouldn't
need Microsoft services to do that." So: no certificate, no Azure, no
keys. The installer ships unsigned by design. What that costs her, and
what the website shows her in pictures: Edge's "isn't commonly
downloaded" → Keep → Keep anyway; "Windows protected your PC" → More
info → Run anyway; then Yes. On the minority of Windows 11 PCs with
Smart App Control on, no unsigned program can run, so the website shows
how to switch it off (one-way, said plainly). Booting needs no keys from
us either: AurOS starts through Ubuntu's already-signed shim/grub, so
Secure Boot stays on with no firmware screens.

### D8. Other OSes (phase 2): install the official, unmodified ones, unattended

From `docs/research/other-systems-2026-10.md`. A rebuilt "Ubuntu"/"Mint"
would have to drop the names (Canonical's IP policy for modified images),
and Mint/Zorin/elementary/Pop apps aren't in Ubuntu's archive. So: the
Windows side puts the official ISO (checked against the publisher's
SHA256SUMS + GPG) in a temporary partition in the gap; BootNext starts the
ISO's own Microsoft-signed shim → grub loopback → the installer with an
`autoinstall` file we write, formatting ONLY the partitions AurOS hands it;
a post-install step restores BootOrder (Windows first until "it works"),
checks no MOK enrolment is queued, removes the temporary partition. Order:
Ubuntu 26.04 LTS → Xubuntu/Ubuntu Cinnamon/Budgie 26.04 → Linux Mint 22.3
(old installer's automatic mode; Mint 23 drops it) → Fedora Workstation
(only one with a 2023-signed shim) → Zorin 18 Core. Not now: Kubuntu,
Lubuntu, elementary, Pop!_OS, ChromeOS Flex, Ubuntu MATE. Names: plain
product names for unmodified images + a "not affiliated" footer, no logos
until permission. Owner action (not urgent): write to Canonical about
names/logos and about AurOS's own image (it ships Canonical binaries in a
modified image — the research flags the "recompile" clause; Mint and
others operate this way with agreements).
